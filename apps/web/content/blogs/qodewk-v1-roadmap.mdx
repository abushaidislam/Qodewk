</TLDR>

## The Trajectory of Autonomous Coding

In less than a month since Qodewk's first public commit, thousands of receipts have been generated by developers using Claude Code, Cursor, Windsurf, Aider, and Antigravity.

We've proven that local-first, privacy-by-construction telemetry is not just feasible—it is the only architecture that developer communities and enterprise security teams can agree on.

As we stabilize the v1.0 milestone, here is our roadmap for the next chapter of Qodewk.

---

## 1. Protocol v1.0 Formal Standardization

In `@qodewk/protocol`, our Zod contracts define the canonical shape of an agent receipt:

- `ReceiptV1Schema`: Unified commit, author, git metrics, telemetry, and cryptographic proof structure.
- `ProviderSessionSchema`: Normalized harvester outputs.
- `AttributionModeSchema`: Provenance guarantees (`observed`, `estimated`, `imported`, `verified`, `unknown`).

We are working with tool authors and community contributors to establish **RFC 01: Universal Coding Telemetry Protocol**, enabling any AI agent or terminal tool to emit native Qodewk receipts directly without requiring reverse-engineered harvesters.

---

## 2. Real-Time IDE Status Bar Integration

Currently, developers view receipts after running `qodewk` in the terminal or after committing changes. 

In upcoming releases, we are introducing lightweight VS Code and JetBrains extensions that display live telemetry directly in your IDE status bar:

```text
[Qodewk: Claude 3.7 Sonnet | ~42k tokens | $0.14 | AI Ratio: 91%]
```

- Real-time token budget consumption alerts.
- One-click copy of thermal receipt markdown blocks.
- Immediate visual feedback on session attribution before making commits.

---

## 3. Monorepo and Multi-Repository Aggregation

Modern engineering organizations manage code across dozens of micro-services and monorepos (Turborepo, Nx, Cargo workspaces).

Our v1.x roadmap includes:
- **Workspace-Level Rollups:** Aggregating receipts across all sub-packages in a Turborepo.
- **Sprint & Epic Attribution:** Tagging receipts with issue identifiers (`#142`, `JIRA-891`) to track total AI capital expenditure per customer feature.
- **Team Heatmaps:** Visualizing which modules in your codebase are heavily generated by agents versus modules requiring predominantly human manual logic.

---

## 4. Cryptographic Peer Attestation

Today, public receipts are signed with a local HMAC-SHA256 signature. In future milestones, we are introducing **Decentralized GPG / SSH Key Attestation**:

1. When an agent generates code, it signs the telemetry bundle with the developer's existing git signing key.
2. Reviewers can verify not only that the git commit was signed, but that the associated AI receipt was cryptographically countersigned by the author's local workstation.
3. Completely immutable, zero-cloud verification of agent provenance.
